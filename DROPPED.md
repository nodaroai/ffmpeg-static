# What the patched ffmpeg does not have

The comparison below is generated by `compare-stock.sh` in the release workflow, against the prebuilt static
build of the same ffmpeg commit (`BtbN/FFmpeg-Builds`, release `autobuild-2026-06-30-13-34`) that this build follows.
Nothing in this build is new relative to the prebuilt (0 added). The component list is covered by
every category the binary reports: encoders, decoders, muxers, demuxers, filters, protocols (as `input:` /
`output:`), bitstream filters, hwaccels and devices. It is also enforced: `stock-only.<arch>.txt` beside this
file is the same list, and the workflow fails when a build's comparison differs from it. The set of optional
libraries that are absent is likewise fixed (`EXPECTED_DROPPED` in `build.sh`).

Why things are gone:

- **Hardware paths** (NVENC/CUDA/QSV/VAAPI/Vulkan/OpenCL/AMF, pulse, x11, DRM, kmsgrab): not usable in a headless server build.
- **Libraries Debian ships no static archive for** (`libsoxr`, `libsvtav1`, `libvidstab`, `libgme`; these four are the approved set `build.sh` enforces): enabling them would make the binary depend on the host's shared libraries.
- **Libraries not packaged in Debian bookworm, or not worth the link risk** (`librav1e`, `libkvazaar`, `libvvenc`, `libopenh264`, `libjxl`, `liboapv`, `libxavs2`, `libdavs2`, `libuavs3d`, `libplacebo`, `libvmaf`, `lv2`, `frei0r`, `libzmq`, `libsrt`, `libssh`, `librist`, `libbluray`, `libdvdread`, `libzvbi`, `libaribb24`, `libaribcaption`, `libopenmpt`, `chromaprint`, `lcevc`, `avisynth`, `libfdk-aac` (non-free anyway)).

None of them is needed for the file-based transcoding this build is meant for.
`libdav1d`, `libharfbuzz` and the five pinned libraries are built from source at the prebuilt's commits
(see `build.sh`), so AV1 decoding and `drawtext` shaping are the same code as before.
